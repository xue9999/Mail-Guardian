# Installation

Choose one mailbox owner: a local Mac worker or a Linux server worker. Do not
start both against the same mailbox. If the mailbox is already managed, follow
the [migration fence](../deploy/linux/MIGRATION_FENCE.md) and preserve the newest
coherent state and trained model before transferring ownership.

## Prepare the account

Check your provider's current IMAP settings. You need implicit TLS, native IMAP
MOVE, an email address, a login name if different, and a password/app password.
Enable IMAP and follow the provider's account security instructions. OAuth-only
accounts are unsupported. See [provider support](PROVIDERS.md).

Use a dedicated app password where available. Never put it into Git, a command
argument, a screenshot or a support report. The macOS wizard accepts it in a
secure field; the CLI reads it without echo. Linux uses private credentials.

## macOS package

Requirements: Apple Silicon, macOS 13 or newer, network access and enough disk
space for the supporting stack and encrypted backups. The worker runs while
the Mac is awake. A missed schedule is caught up once after waking; this is not
continuous server availability.

1. Obtain a deliberately published macOS archive from
   [Releases](https://github.com/xue9999/Mail-Guardian/releases). Source ZIPs
   generated by GitHub are not prebuilt applications.
2. Check the version and available checksum. A checksum detects corruption;
   it does not authenticate an otherwise untrusted publisher or download.
3. Extract the package and open `Install.command`. Read its prompts. The
   installer prepares Colima, Docker/Compose and the local filtering stack.
4. If macOS blocks opening the command, use Control-click → Open only after
   verifying the source. Do not disable system protections globally.
5. Wait for the application, then follow the [desktop guide](DESKTOP-GUIDE.md).

Packages use local ad hoc signing, without Developer ID or Apple notarization.
A package contains prebuilt Go and Swift programs; it does not compile them on
the recipient's Mac. Installing from the source checkout builds them and needs
full Xcode and the accepted Go compiler (see [CONTRIBUTING](../CONTRIBUTING.md)).
The minimum declared OS version is not evidence of testing on every older Mac.

## Source checkout

```sh
git clone https://github.com/xue9999/Mail-Guardian.git
cd Mail-Guardian
make build build-recovery
make test
```

Building and testing do not configure an account. To deliberately install the
Mac application, run `Install.command` from the checkout. For isolated package
validation, follow the contributor guide instead of installing onto a real
operator account. Installer logs retain the legacy location
`~/Library/Logs/O2 Mail Guardian/instalacja.log` for upgrade compatibility.

## First connection

Select Custom IMAP, enter the hostname, implicit TLS port and optional separate
login. The o2 preset is available explicitly. Supply the email address and
secret, then probe the connection. Confirm the detected spam folder and shown
Guardian folder names. Existing training-folder contents require explicit
acceptance because they become user corrections on a live run.

Save the configuration and complete a safe dry-run. A successful dry-run
unlocks the choice of manual operation or automatic checks. It does not enable
active Inbox cleanup or permanent deletion. Review the first results and keep
uncertain mail in review.

## Updating an existing installation

Keep a coherent backup of configuration, database, encrypted message archive,
archive key and trained model before changing an active worker. Use the newest
compatible state. The installer stages replacements, checks binaries/manifests
and attempts rollback on failure; retain its backups if rollback is incomplete.
Do not assume an installer success means a real mailbox run succeeded.

The English product name preserves historical installation paths and service
identifiers. Existing folders and mailbox identity remain unchanged. See
[upgrade compatibility](PROVIDERS.md#upgrade-compatibility). Do not change a
populated installation's endpoint to reuse its state with another mailbox.

## Linux

Use the complete [Linux installation procedure](../deploy/linux/README.md).
`server init-config` now defaults to Custom IMAP and requires an explicit host;
use `--provider o2` for the historical preset. Installation leaves scheduling
off. Credential provisioning, identity/policy acceptance, a fresh dry-run and a
supervised real run precede timer activation. Root maintenance tools are not
part of ordinary local development.
